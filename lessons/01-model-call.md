# 第一课：看清一次模型调用

本课目标：你能指出消息从哪里进入、请求怎样发出、回答在哪里返回，以及下一轮对话需要保存什么。

完成这些实验以后，再进入工具调用。预计需要 2～4 小时；以你能独立解释为准。

## 先理解今天的五个词

| 名称 | 在这个项目里的含义 |
| --- | --- |
| 模型 | 远程服务中根据消息生成输出的程序；通过 `model` 指定 |
| 消息 | 一个带有 `role` 和 `content` 的记录 |
| 上下文 | 本次请求中提供给模型的信息；今天主要是 `messages` |
| 请求 | 你的程序发送给服务的一份 HTTP 消息，其中包含 JSON 请求体 |
| 响应 | 服务返回的 JSON，包含回答、停止原因和用量等信息 |

`system` 用来提供本次对话的总体要求，`user` 是用户输入，`assistant` 是模型回复。后面的课程还会增加 `tool`，用于回传工具执行结果。

今天只调用模型并打印响应。下一课才让模型提出工具调用，再由我们写的程序执行工具。

## 实验一：不花 API 用量，观察请求

运行：

```powershell
python chat.py --preview "你好，我正在学习 Agent 开发。"
```

观察输出，找到 `model`、`messages`、`stream` 和 `max_tokens`。

先写下你的预测：

1. 修改命令里的那句话，请求中的哪个字段会变？
2. 把系统提示里的“简洁的中文”改成“英文”，你预计回答会怎样变化？
3. `max_tokens` 限制的是输入长度、输出长度，还是 Python 程序的运行次数？

`max_tokens` 是输出 token 上限；token 不等于固定数量的汉字。`stream: false` 表示我们等待完整响应，不逐段处理输出。

## 实验二：运行一次真实调用

运行：

```powershell
python chat.py "请用两句话解释什么是 Agent。"
```

在本地终端的提示处输入自己的 API Key。不要将密钥粘贴到源码、实验笔记或聊天中。

在返回 JSON 中找到：

- `choices[0].message.content`：模型的回答。
- `choices[0].finish_reason`：本次生成停止的原因。
- `usage`：请求的 token 用量信息。

预期能够找到文字回答。若 `finish_reason` 是 `length`，说明达到了长度限制，回答可能没有说完；不要把这种情况自动当成任务完成。

当前源码没有把 API Key 配置进环境，也没有真实调用验证。完成这一实验后，在学习记录中写下实际结果。

常见错误：

- HTTP 401：检查密钥是否有效、是否复制完整。
- HTTP 402：检查服务账号余额。
- HTTP 400：检查模型标识和请求字段是否符合当前接口。
- HTTP 429：检查频率限制，稍后再试。
- 连接失败或超时：检查网络和代理。

请记录错误码和现象，不记录密钥。

## 实验三：做第一次独立修改

修改 `chat.py` 最后的显示部分，让它在打印原始 JSON 之外，再单独打印：

1. 一行“助手回答：”，后面是回答内容。
2. 一行“停止原因：”，后面是 `finish_reason`。

先自己写，遇到困难时查列表与字典的取值方法，或让老师解释局部语法。暂时保留原始 JSON，方便你核对取值是否正确。

验收：你能在原始 JSON 中指出这两项的来源，修改后程序仍然可以运行。

## 实验四：设计两轮对话

暂时不要求立即实现。先在纸上或笔记里写出第二次请求的 `messages`：

第一轮用户说：“我的练习项目叫小灯。”

第二轮用户问：“我的练习项目叫什么？”

第二次请求通常需要包含：原来的 system 消息、第一轮用户消息、第一轮 assistant 回复、新的用户消息。DeepSeek Chat Completions 的多轮上下文由客户端在请求中组织。

请比较两个实验方案：第二次请求只发新的问题；第二次请求带上上述历史。你预测它们有什么区别？注意：即使回答碰巧猜对，也要检查模型实际收到了什么。

下一次我们会根据你的设计，把第二轮请求接进程序，再做“保留历史”和“去掉历史”的对照实验。

## 阅读源码的顺序

1. 找 `messages`：模型从哪里获得输入？
2. 找 `payload`：本次请求还包含哪些设置？
3. 看 `call_model`：JSON 怎样编码、发出并变回 Python 数据？
4. 找最后两行 `print`：程序目前怎样展示响应？

当前直接使用标准库发 HTTP 请求，便于观察 JSON。HTTP 库本身不属于 Agent 的推理或工具循环。
